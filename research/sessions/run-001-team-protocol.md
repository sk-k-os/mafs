# Shared research and collective success

Recorded October 28, 2026 during the first live research run. The director requested collaborative teams with shared information and a shared interest in solving the problem. This is a scientific operating decision, not evidence that any given team will outperform an individual.

## Shared objective and information

All teams work toward the same exact BSD target and its separately tracked obligations. Findings, source locators, mathematical arguments, computations, anomalies, objections, failed approaches and useful context go into the common research record. Teams should publish useful intermediate information promptly and name dependencies so another team can use or challenge it. No team owns a private mathematical result or benefits from hiding a correction.

Use discussion to combine complementary methods. The source team maps the strongest applicable known theorem. The computation team supplies exact examples and tests. The argument team develops bridges from those observations to named proof obligations. Reviewers reconstruct claims and expose defects. Their findings return to every team. Independence means checking an argument oneself and recording shared dependencies, not withholding evidence.

The common measure of progress is justified understanding: a supported relevant result, a resolved objection, a reproducible observation, or a useful failure that rules out a route. Naming contributors preserves provenance and review conflicts; it does not award competing ownership. A reviewer who catches a flaw advances the shared objective. Output volume, confident language and agreement are not success measures. No numeric reward system or productivity benchmark is implemented by this record.

## First run assignments

The first run combines a source applicability audit of the analytic rank one prime part theorem, exact small finite field computations on the pilot and controls, an explicit mathematical bridge where supported, and a separate review. The coordinator shares intermediate findings, reconciles objections and owns Git writes. Workers use separate files in the same checkout and may inspect published evidence from other teams.

This is a bounded calibration run using currently available tools. It does not establish a persistent six account runtime, formal proof verification, or an absence of hallucinations. New roles are added only for a concrete unanswered question within the actual concurrency and resource bounds.

## Continuity

Before replacement or completion, save precise claims, evidence revisions, unresolved objections, failed routes and the next test. Successors receive the shared record and validate the cited evidence. Corrections remain visible. Retiring a worker must preserve its contributions and cannot turn an unresolved claim into an accepted one.
