# Mathforge research observatory

The accompanying `hud.html` is a self contained interactive design preview. Open it in a browser. It embeds Montserrat and requires no server, account, package installation, or network connection. BSD over Q is the selected target. The operator serves as human research director. The preview is not connected to a research runtime, model, conversation adapter, proof assistant, database, or telemetry system.

The preview persistently displays **DESIGN PREVIEW · SYNTHETIC DATA · NO ACTIVE RESEARCH**. It must retain this status until a separately verified runtime integration exists. There is no percentage of BSD solved and no claim of new mathematical progress.

Every slot explicitly shows **Account login: Not connected**, **Plan: Unknown**, **Remaining usage: Unknown**, and **Reset: Unknown**. Shared pool membership is unknown. There is no aggregate percentage, inferred quota, synthetic consumption estimate, or invented plan. Capacity must be inspected per account and bound to the correct identity before dispatch. Supported authentication and account assignments remain unverified.

The public template has no account or usage authorization. The proposed additional spending ceiling is zero. Mathematical value, scope and verification determine work selection. Current operator decisions must bind any actual campaign.

A proposed deterministic broker is ordinary application logic and does not consume a seventh subscription. It routes versioned structured handoffs containing the frozen task and target, direct source artifacts, assumptions, facts, conjectures, exact results, failures, checking receipts, and ownership. Each transition has an explicit dependency and result contract.

The intended route is scoped assignment, structured evidence packet, blind review, then synthesis. The independent referee’s first pass receives the claim, original sources, and checking task without the author’s persuasion or other reviewers’ verdicts. The coordinator receives the recorded assessment and objections before synthesis. Further work is assigned through bounded tasks with evidence requirements. There is no unrestricted everyone talks to everyone loop.

The existing illustrative roster and benchmark numbers remain visibly labeled synthetic and cannot be read as account capacity or measured performance of these six unconnected slots. Font assets, source evidence, the full BSD solution contract, and all five unreached solution stages remain intact.

## Screen behavior

1. Select a dependency node or timeline row. Both select the same activation and update the claim inspector. Every fixture has one attempt; a production view must preserve each later attempt separately.
2. Switch between input and output JSON. The current tab remains selected while changing nodes. All source content is rendered with `textContent`, never interpreted as markup.
3. Use Tab and Enter or Space to select graph nodes. Payload tabs support arrow keys, Home, and End. Important selection changes have a brief accessible announcement.
4. Inspect the succession packet. Its dialog supports the native Escape key and restores focus when closed.
5. Follow the section navigation to teams, ideas, or the director’s human checkpoint. Review controls are disabled; they perform no real or simulated launch.
6. Read the solution contract. Its five stages all remain unreached. Mathematical proof status and external recognition are separate records.

The design uses restrained cyan for a finite fixture pass, amber for held evidence and human waiting, red for a rejected assertion, and violet for speculative exploration. Status text carries the meaning independently of color. Narrow layouts stack the panels. The graph and evaluation table retain internal horizontal scrolling when their content cannot fit legibly.

## Research conversations with the director

The operator serves as human research director. Agents should bring him useful questions when a new idea, choice of representation, unresolved obstacle, priority, or scope decision could improve the work. Each question should include the smallest useful context, what has been tried, the evidence, and concrete alternatives while leaving room for an unconventional suggestion.

The director’s response can create new hypotheses, counterexamples to seek, definitions to examine, literature leads, or bounded experiments. The system must retain the exact response and distinguish its interpretation from any applied workflow change. A direction from the director is not a proof certificate or a substitute for independent mathematical validation. Conversation is a source of ideas; all ideas face the same evidence requirements.

## Solution contract

The selected objective is the full Birch and Swinnerton Dyer conjecture over Q, for every elliptic curve E over Q. A complete solution must establish all three obligations with consistent definitions and normalizations:

1. The analytic order of vanishing at s = 1 equals the rational Mordell Weil rank r.
2. The Tate Shafarevich group Sha(E/Q) is finite.
3. The leading coefficient obeys L^(r)(E,1)/r! = Ω_E · Reg_E · #Sha(E/Q) · product of c_p / #E(Q)_tors².

The screen carries five explicit stages. **Candidate complete** means an entire proof argument is assembled without essential unresolved gaps. **Internally verified** requires independent internal adversarial review and a precise record of formal coverage and trust assumptions. **Independently validated** requires qualified external mathematical review of the complete argument. **Solution accepted** requires the director to accept the independently validated bundle under a recorded assurance profile, with current reproducibility checks and no hidden conditional premise. The director’s acceptance acknowledges evidence and cannot override a failed or missing check. **Externally recognized** records recognition supported by external evidence, separately from the program’s acceptance state.

The assurance profile has not been selected. The proposed default, `formalComplete`, requires the intended statement and all required proof dependencies to be checked under approved foundations with current replay receipts and independent review of mathematical meaning. An explicitly selected `expertProof` profile requires at least two independent qualified reviewers, including one with BSD expertise, written reports, closed material objections, and certified computational ingredients. Partial formal coverage must be displayed. Switching profiles requires an explicit recorded decision; a mathematical defect blocks both. The [full solution contract](references/solution-contract.md) governs these transitions.

No stage has passed. No solution has been established. All present activity remains a synthetic design preview. A materially revised argument invalidates any review evidence that no longer applies.

The program’s mathematical proof status is distinct from recognition by the mathematical community and any Clay decision. A dashboard, agent vote, internal benchmark, or human approval cannot award Clay recognition. Numerical agreement, a restricted theorem, and a promising proof sketch do not satisfy the full solution contract.

## Mathematical examples and limits

**Numerical BSD agreement is held.** A synthetic proposal about curve 37a1 has no executed command, environment, output artifact, or certified precision. The preview deliberately supplies no invented computed numerical value. Even reproducible agreement for one curve would not establish the general conjecture.

**A universal rank equality is rejected in the illustrative audit.** The assertion that the dimension over F2 of E(Q)/2E(Q) always equals the rank of E(Q) omits rational 2 torsion. Under the Mordell Weil structure theorem, the dimension includes dim E(Q)[2]. The curve y² = x³ − x has three nonidentity rational points of order two, contributing dimension two. The preview carries an explanatory counterexample, not a machine checked proof certificate.

**One elementary finite control passes.** The JavaScript enumerates all four elements of Z/4Z and checks that their squares lie in {0,1}. The result is explicitly restricted to the finite fixture. No Lean kernel has been invoked. This control is a demonstration of a validation boundary, not a research achievement.

Dependency edges represent task prerequisites, not logical implication edges in a proof. A production mathematical claim graph needs a separate typed relation for implication, conditional dependence, equivalence, contradiction, and analogy, including hypotheses and evidence references.

## Evaluation and succession

The agent table shows illustrative accuracy counts on an assumed matched difficulty cohort, with Wilson 95 percent intervals rounded to whole percentages. These records are synthetic, not observed model performance. Agents are not ranked by verbosity, time spent, claimed novelty, or number of conjectures generated.

The displayed sample size is explicitly too small to infer a productivity decline. A critical unsupported claim opens diagnostic review and quarantine. It does not establish that a model has become less capable. Difficulty, allowed tools, task distribution, context length, budget, repeated trials, and evaluator agreement must be controlled before comparing longitudinal performance.

The proposed successor has no score and remains unlaunched. Its transfer packet preserves fact status, rejected claims, open questions, evidence references, context revision, omissions, and required checks. An immutable source reference is proposed; the prototype does not imply that a missing source has been preserved. A derivative summary remains untrusted until reconciled against those sources. Transfer comprehension and held out evaluation must precede promotion.

## Runtime integration requirements

This prototype does not implement production authorization, source retention, redaction, request capture, replay, cost accounting, background scheduling, isolation, or agent lifecycle management. Display labels cannot enforce any of these properties.

A production build needs an authenticated snapshot and event service; separate payload access; stable run, graph, activation, attempt, call, and event identities; monotonic durations; replay cursors and gaps; current authorization checks; and immutable evidence references. The event digest currently contains three selected design events, not a complete trace.

Actual provider input and output must be labeled separately from application JSON. Missing capture, expired evidence, withheld fields, and unbound tools must remain explicit. Exact source records must not be reconstructed from a model summary. No private internal reasoning is required for oversight; inspectable claims, concise explanations, assumptions, commands, outputs, and evidence are the appropriate artifacts.

Human checkpoint actions require a versioned question, review packet, authorized reviewer, trusted response record, and explicit applied transition. An approval is distinct from mathematical correctness. Selecting a node, reading a checkpoint, or opening this file must never resume work.
