# Capability catalog

Checked October 28, 2026. Researching a capability does not install it. Installation does not establish scientific reliability. Each integration needs pinned versions, a trusted adapter, a successful control, a seeded failure, and a reproducibility receipt.

## Actual local state

Codex CLI 0.155.0 alpha.9.2 and the Agent Tools package were found. Node and Python were found. Lean, Lake, and Sage were not found on the inspected PATH. That does not prove they are absent from every machine. The DGX Spark, Mac Studio, EXO network, model inventory, and remote software have not been inspected or benchmarked in this task.

The delivered launcher uses the actual Codex CLI. The mathematical tools below are researched candidates. No remote mathematics service, GPU instance, or paid provider was provisioned.

Do not install every mathematical package or online agent prompt. Add a capability when a specific accepted assignment needs it. Prefer an official repository or documented upstream package. Review licenses and execute new code only in the qualified environment. Keep discovery retrieval separate from code execution.

Automated theorem proving benchmarks can measure tactic search on their distribution. They do not demonstrate readiness to discover or prove BSD. A capability should earn its place by improving a matched task under the same resource budget without weakening verification.

## Computational independence

Sage can call PARI and eclib. Comparing outputs from two interfaces to the same underlying engine is replication of an interface path, not an independent arithmetic implementation. Record engine lineage. Small exhaustive computations written from definitions can provide a separate check for bounded quantities; they do not certify the entire global theorem.

## Proposed tool contracts

These names correspond to ProposedAdapters in contracts.ts. They are not current MCP tools.

| Contract | Purpose and when called | Inputs and starting result | Output and evidence | Effects and failure |
| :--- | :--- | :--- | :--- | :--- |
| fetchSource | Retrieve a specific permitted mathematical source | URL, expected version, allowed destination | Immutable bytes, hash, timestamp, source identity and extraction boundaries | Write source artifact only; denied URL or unavailable source returns explicit failure |
| runIsolatedComputation | Execute a bounded experiment whose claim is specified | Pinned program and input hashes, image digest, proof settings, limits | Exact output, logs, engine versions, assumptions and resource receipt | Isolated job and artifacts; no host fallback, timeout remains incomplete |
| verifyFormalProof | Assess a candidate against an immutable challenge | Claim revision, proof source, target and toolchain | Trusted receipt for target match, dependencies, replay and semantic review | Verifier owns receipt; missing required check returns inconclusive |
| proposeSpecialist | Request a missing bounded capability | Definition, assignment, capability gap evidence | Accepted definition or rejection with reasons and reserved budget | Controller alone creates a worker; no child permission expansion |
| submitCandidate | Place evidence into a review queue | Exact claim and artifacts | Candidate identity and review receipt | Cannot promote own result; invalid references reject submission |
| recordHumanDecision | Apply an authenticated decision to reviewed scope | Exact response, role, packet revision and disposition | Durable decision and transition receipt | Stale or unauthorized decision is rejected; duplicate returns original result |

Artifact identifiers and hashes are resolved by trusted code. A model supplied `verified: true` field has no authority. All input validation, source access checks, budget reservation, and status transitions need actual implementations and direct adapter tests.

## Models and hardware

Use the user's configured model for the delivered interactive launcher. For the later service, benchmark candidate model configurations against known mathematical tasks, referee tasks, tool use, and context fidelity. Choose by measured results at matched cost. Long reasoning output alone is not evidence of better mathematics.

An EXO connection or successful model load establishes availability, not proof competence. Verify concurrency, context capacity, tool calling, output schema reliability, throughput, and error rates on the actual DGX and Mac configuration before assigning roles. Keep local inference, cloud inference, human time, and computation accounting separate. No claim about their performance is made here.
